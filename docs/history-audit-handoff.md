## 核查方法（照此执行）

- **一条一条核，不要整年重扫。** 每核一条就写进索引，并设 `checkedAt`。没写进索引的核查，下一轮无法知道它做过。
- **verified 的门槛**：至少一个来源能打开、并**直接**写出日期和核心说法（`evidenceStatus: direct`）。只有百科来源也可以，但 `sourceType` 要如实标成 `tertiary`。来源的优先级为：原始文件（专利、法令、决议）> 机构官网（NASA、NARA、诺贝尔奖官网、博物馆）> 学术或媒体 > 维基百科。
- **日期是这张卡片的核心。** 日期只有一个叙事来源、只能确定到年或季节、或者存在争议的，不要硬写：
  - 能改写成不依赖精确日期的说法就改写；
  - 不能就换成同一天无争议的事件，并先查 `HISTORY[MM-DD]` 和其余 `HISTORY_MORE`，避免重复。
  - 儒略历日期要注明。
- **中英文必须一致。** 本轮就发现 03-26 中文写“上万”、英文写 “tens of thousands”。两种语言都要对照来源。
- **“首次 / 唯一 / 最大 / 最古老”这类说法最容易出错。** 来源怎么限定就怎么写，比如“现存在轨最古老”“首次成功的水上飞机”。
- **长度**：目前中文最长 56 字、英文最长 220 字符，改写时不要超过，以免卡片排不下。
- **提交前运行** `node tests/content.test.cjs`。它检查 id、日期，以及与 `HISTORY` 是否重复；不检查事实。
- **抓取提示**：维基、NASA、NARA、govinfo、Google Patents、nobelprize.org、un.org 都能直接抓取，Google Patents 连续请求会被限流。britannica.com、vangoghmuseum.nl、rkd.nl、olympics.com 会被拦截或连不上。

## 索引字段速查

见 `docs/history-sources.json` 中的 `statusDefinitions` 和 `sourceFieldDefinitions`。每条记录：

```json
"history:MM-DD:2": {
  "year": 1910,
  "status": "verified",
  "sources": [{ "publisher": "...", "url": "...", "claim": "这个来源具体支持什么",
                "sourceType": "primary|official|secondary|tertiary",
                "accessStatus": "accessible|restricted|unreachable",
                "accessCheckedAt": "YYYY-MM-DD",
                "evidenceStatus": "direct|partial|unconfirmed",
                "provenance": "direct_fetch" }],
  "notes": "改了什么、为什么；还缺什么",
  "checkedAt": "YYYY-MM-DD"
}
```

替换或改写事件时，同时更新 `year`，并在 `notes` 里写明原事件和替换原因。
